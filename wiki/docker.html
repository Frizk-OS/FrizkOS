Docker Build Environment

Isolated legacy toolchain setup for compiling FrizkOS.

Building legacy Android source trees (like KitKat 4.4.4) on modern Linux distributions will result in fatal compilation errors. The legacy C/C++ toolchains, specifically GCC 4.7, are incompatible with modern glibc and make versions. To avoid polluting the host system and ensure a reproducible build, we strictly mandate the use of a Docker container based on Ubuntu 14.04.

1. The Dockerfile

Create a Dockerfile in a separate directory. This configuration pulls the correct base image and installs all necessary dependencies for C/C++ compilation, Java, and repository management.

FROM ubuntu:14.04

ENV DEBIAN_FRONTEND noninteractive
ENV USER build

# Update and install build dependencies
RUN apt-get update && apt-get install -y \
    bison build-essential curl flex git gnupg gperf \
    libesd0-dev liblz4-tool libncurses5-dev libsdl1.2-dev \
    libwxgtk2.8-dev libxml2 libxml2-utils lzop openjdk-7-jdk \
    pngcrush schedtool squashfs-tools xsltproc zip zlib1g-dev \
    g++-multilib gcc-multilib lib32ncurses5-dev lib32readline-gplv2-dev \
    lib32z1-dev python-minimal

# Install Repo tool
RUN curl http://commondatastorage.googleapis.com/git-repo-downloads/repo > /usr/local/bin/repo \
    && chmod a+x /usr/local/bin/repo

# Create build user
RUN useradd -m -s /bin/bash $USER
USER $USER
WORKDIR /src

CMD ["/bin/bash"]

2. Building the Image

Execute this command in the directory containing your Dockerfile to construct the image. This process only needs to be done once.

docker build -t frizkos-build-env .

3. Running the Container

When starting the container, you must map your local source directory to the /src directory inside the container using the -v flag. This ensures that the downloaded source code and compiled object files remain on your host machine after the container is destroyed.

docker run -it --rm \
  -v /path/to/your/frizkos_src:/src \
  frizkos-build-env
Memory Warning: Ensure your Docker daemon has access to at least 16GB of RAM and sufficient swap space. The linker (ld) will consume massive amounts of memory when processing the native C++ webkit and framework binaries.
